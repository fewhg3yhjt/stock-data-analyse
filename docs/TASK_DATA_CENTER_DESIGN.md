# 任务中心与数据中心前端设计

## 1. 目标

任务中心和数据中心是两个用户视角：

```text
数据中心：系统有哪些实际数据和指标，最新到哪里，覆盖如何，是否正常
任务中心：有哪些工作，何时执行，执行到哪，生成了什么
```

不把 Raw Batch、Candidate、Quality Report、文件分区或日志统计为数据资产。它们只在任务详情和技术详情中出现。

## 2. 页面结构

```text
数据中心
├── 数据总览
├── 数据资产
└── 任务中心
```

### 数据总览

只展示实际数据/指标项的汇总：

- 数据项总数；
- 正常、待更新、异常数量；
- 当前运行任务；
- 今日完成任务；
- 重点数据项；
- 当前任务进度。

资产总数的口径是“启用的数据集和指标定义”，不包含阶段、版本、文件和日志。

### 数据资产

资产列表字段：

- 名称；
- 分类；
- 数据粒度；
- 最新实际日期/周期；
- 覆盖数量和覆盖率；
- 健康状态；
- 关联任务；
- 更新时间。

顶部日期筛选只表示“查看实际日期范围”，不把交易日作为用户需要理解的配置。当天没有数据就按实际结果展示为空或滞后。

点击资产后打开详情抽屉或右侧详情面板：

- 定义和统一口径；
- 输入数据；
- 关联任务；
- 最新实际日期；
- 股票覆盖；
- ETF 覆盖；
- 其他证券类型覆盖；
- 健康说明；
- 当前结果预览。

股票和 ETF 是详情中的实际数据维度，不拆成两套页面。对于不适用的指标显示“不适用于该证券类型”，不计入缺失。

### 任务中心

任务列表按任务组展示，任务是可执行对象。列表字段：

- 任务名称；
- 任务阶段；
- 任务类型；
- 执行周期；
- 当前状态；
- 进度；
- 开始时间；
- 耗时；
- 最近结果。

任务状态使用 `docs/TASK_DATA_GLOSSARY.md` 的统一状态，不另造“生产状态”。

任务详情使用四个区域：

```text
执行概览 | 配置 | 日志 | 结果与关系
```

运行中和已完成任务都可以查看日志和结果。运行中默认短轮询刷新，日志可暂停刷新；已完成任务显示完整日志。

## 3. 任务操作

```text
查看详情
立即执行
补数据
查看日志
查看产物
查看数据预览
查看上游/下游
重新执行
```

高风险操作（启停调度、配置生效、发布、回滚、批量补数据）显示影响范围并二次确认。

## 4. 数据资产操作

```text
查看定义
查看健康
查看股票/ETF覆盖
查看关联任务
查看当前结果
编辑可配置指标
停用自定义指标
重新生成
```

基础行情等基础指标不能删除或修改核心口径；可配置指标修改后生成新版本并标记待更新。

## 5. API 数据契约

```text
GET /api/data-center/overview
GET /api/data-center/assets?category=&status=&date=
GET /api/data-center/assets/<metric_key>
GET /api/task-center/overview
GET /api/task-center/tasks
GET /api/task-center/tasks/<task_key>
GET /api/task-center/runs/<run_id>/events
GET /api/task-center/runs/<run_id>/logs
GET /api/task-center/runs/<run_id>/artifacts
GET /api/artifacts/<artifact_id>/preview
GET /api/artifacts/<artifact_id>/lineage
```

API 返回内部英文值和用户可读 label，前端不直接拼底层表字段。

## 6. 实现边界

- 第一版页面使用短轮询，不引入 WebSocket；
- 文件预览只读、限制行数和允许目录；
- 数据资产统计基于实际数据集/指标定义，不统计技术产物；
- 任务配置的执行周期和本次运行实际日期分开显示；
- 股票和 ETF 的覆盖统计按证券类型分开；
- 没有类型覆盖统计时明确显示“暂无类型覆盖数据”，不显示空白或伪造 0；
- Raw、Candidate、Quality、checksum、血缘等技术信息折叠展示；
- 生产切换、发布和回滚操作不因页面实现而自动开启。

管理库切换采用独立开关：页面和管理服务通过 `MANAGEMENT_DB_PATH` 指向新管理库；未设置时保持现有兼容路径。新管理库使用 `management.db`，由显式迁移工具创建和导入；切换前必须完成定义导入、旧事实迁移、小量链路验证和新旧查询对账；旧库不自动删除。
