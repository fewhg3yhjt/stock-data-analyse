# 任务与数据术语

本文是任务中心、数据中心、API 和后续页面的统一用词依据。

辅助数据采集由任务配置驱动。行业、财务史、估值和资金流分别使用
`config/tasks/industry_capture.yaml`、`fundamentals_capture.yaml`、
`valuation_capture.yaml` 和 `money_flow_capture.yaml` 的 `schedule.enabled`
决定是否参与调度；不得使用环境变量单独绕过任务配置。AkShare、Baostock
等依赖以生产运行环境为准，不以宿主机 Python 环境的安装状态判断数据源可用性。

## 一、对象边界

| 对象 | 用户理解 | 系统职责 |
|---|---|---|
| 任务 | 要执行的一件工作 | 采集、构建、检查、发布或计算 |
| 任务阶段 | 任务处于数据流程的哪一步 | 采集、构建、质量、发布、派生计算、维护 |
| 任务类型 | 任务具体做什么 | 源数据采集、标准数据构建、质量检查等 |
| 执行记录 | 某一次任务实际执行 | 状态、进度、周期、日志和错误 |
| 数据文件 | 任务产生或使用的文件 | Raw、候选、正式结果、报告等 |
| 数据版本 | 某个分区或结果的版本 | 当前版本、历史版本、回滚关系 |
| 指标定义 | 指标是什么以及如何计算 | 名称、口径、单位、关联任务 |
| 指标健康 | 指标结果是否更新和覆盖充分 | 最新周期、覆盖数量、覆盖率、状态 |
| 数据血缘 | 数据的来源和去向 | 上游输入、生成任务、下游使用 |

## 二、任务阶段

阶段只描述生命周期位置，不描述文件或运行记录。

| 内部值 | 用户名称 |
|---|---|
| `CAPTURE` | 数据采集 |
| `BUILD` | 数据构建 |
| `QUALITY` | 数据质量 |
| `PUBLISH` | 数据发布 |
| `DERIVED` | 派生计算 |
| `MAINTENANCE` | 数据维护 |

## 三、任务类型

| 内部值 | 用户名称 |
|---|---|
| `SOURCE_CAPTURE` | 源数据采集 |
| `DATA_BUILD` | 标准数据构建 |
| `QUALITY_CHECK` | 数据质量检查 |
| `DATA_PUBLISH` | 数据正式发布 |
| `INDICATOR_BUILD` | 技术指标计算 |
| `FACTOR_BUILD` | 研究因子计算（历史/兼容任务，目标废弃） |
| `LEGACY_CONVERT` | 历史数据转换 |
| `DATA_REPAIR` | 数据修复 |

## 四、任务运行状态

数据库和 API 内部值保持英文，页面使用用户名称。

| 内部值 | 用户名称 |
|---|---|
| `requested` | 已请求 |
| `scheduled` | 已排期 |
| `waiting` | 等待执行 |
| `running` | 执行中 |
| `success` | 已完成 |
| `partial_success` | 部分完成 |
| `skipped` | 已跳过 |
| `failed` | 执行失败 |
| `cancelled` | 已取消 |
| `blocked` | 已阻断 |

## 五、数据产物

这些是技术产物，不是任务阶段。

| 内部值 | 用户名称 |
|---|---|
| `raw_batch` | 原始采集数据 |
| `current_raw` | 去重后的当前有效原始数据 |
| `candidate` | 待发布标准数据 |
| `quality_report` | 质量检查报告 |
| `published_dataset` | 正式数据 |
| `indicator_output` | 技术指标结果 |
| `factor_output` | 研究因子结果（历史归档，目标不再新增） |
| `diff_report` | 新旧结果差异报告 |
| `log` | 执行日志 |

`Raw Batch`、`Candidate`、`Quality Report` 和 `Published Version` 只在任务详情或技术详情中使用，不作为数据中心首屏分类。

## 六、数据中心分类

数据中心按用户关心的数据内容组织：

```text
基础行情
估值数据
基本面数据
技术指标
资金流指标
业务指标
```

研究因子在目标架构中并入技术指标；历史 `factors` 文件、旧任务和兼容术语在清理完成前保留，但不得作为新的生产输入或新增消费契约。

指标定义和指标健康是数据中心的主信息；任务、文件和血缘是关联信息。

## 七、禁止混用

- 阶段不是产物；
- 任务类型不是数据类型；
- 任务结果不是文件本身；
- `success` 只表示任务执行完成，不表示数据质量合格；
- `PASS` 只表示质量结论，不表示任务一定成功生成了正式版本；
- 指标定义不是指标结果；
- 指标健康不是任务状态；
- 目标架构中 `Indicators` 是统一派生计算入口，`Factors` 仅表示历史/兼容产物，不得新增独立生产链路；
- Raw 文件不能称为正式数据；
- Candidate 不能称为当前数据；
- Shadow 发布只能称为“隔离验证发布”，不能称为生产正式发布。

## 八、存储职责

```text
YAML       数据集、任务和指标的声明性定义
SQLite     配置版本、执行记录、健康状态、版本指针和血缘事实
Parquet/CSV 原始数据、标准结果和派生结果文件
```

配置定义和执行事实不得互相替代。文件路径是技术信息，不能替代数据定义或任务状态。

## 九、数据链模块职责

数据链各模块的详细边界以 [数据平台与可信数据链路设计](DATA_PIPELINE_V1_DESIGN.md#44-数据链模块角色与职责) 为准。简要规则如下：

| 模块 | 核心职责 |
|---|---|
| Capture / Source Adapter | 请求外部来源、解析响应、记录采集结果 |
| Raw Batch | 保存源头字段原值和采集批次事实 |
| Current Raw | 按 `date + code` 合并去重，提供当前有效原始视图 |
| Build / Cleaning | 清洗、标准化、单位转换、合并并生成 Candidate |
| Quality | 对 Candidate 做质量判断并形成门禁结论 |
| Publish | 发布通过质量门禁的指定版本并更新 Current |
| DatasetAccess | 只读取 Published Dataset 并返回数据上下文 |
| Indicators | 基于 Published 上游数据生成派生指标 |
| Business Consumers | 使用 Published 数据完成业务功能 |

Raw 不做单位转换；单位转换属于 Build / Cleaning，并且必须由数据集 YAML 配置驱动。Raw Batch 是采集证据，Current Raw 是按 `(date, code)` 去重后的有效原始视图；最终 Candidate 也不得存在重复业务键。任务成功不等于质量合格，Candidate 也不等于正式数据。

### 历史异常处理范式

历史异常数据不直接扩展生产 Build 的默认兼容逻辑。统一由一次性处理脚本按单日执行：先从历史 Raw 还原到预期的源头运输格式，再按 `date + code` 唯一化，生成日期级 Current Raw；遇到无法确认的单位、来源或证券状态时，暂停该日期并请求确认。

```text
历史 Raw
  -> 单日提取
  -> 源头格式还原
  -> date + code 去重
  -> 日期级 Current Raw
  -> 现有 Build / Quality / Publish
```

执行顺序固定为最新月份向历史月份逆序推进：`2026-09`、`2026-08`，依次向前至 `2023-09`。每完成一个月份，必须复查覆盖率、单位异常、重复键、日期范围和版本血缘后，才允许进入下一个月份。

以下情况不得自作主张继续：候选单位不唯一、同一主键多种值无法判定、重新抓取仍为空但证券仍有效、证券状态与 Universe 冲突、需要删除整个 Raw Batch，或需要修改生产 `warehouse/`、`ops/` 代码。应保留失败事实并向负责人说明证据、影响和选项。

历史脚本可以在负责人确认后精确删除指定 `(date, code)` 记录并重新抓取；不得删除整个 Raw Batch 来掩盖单条异常。删除前必须固定日期、证券数量和文件范围，删除后校验 Parquet 可读、目标键已移除、非目标数据未改变，再进入正式链路。

## 十、任务执行的统一入口

以下方式都必须生成统一的执行请求并进入同一个 Runner：

```text
定时执行
手动执行
补数据
失败重试
隔离验证
```

区别只体现在 `trigger_type`、周期区间、证券范围和请求人，不应因为触发方式不同而复制任务业务流程。

## 十一、完成度分层

```text
代码/API 存在       能力骨架已创建
定向测试通过        局部行为成立
临时/持久化样例通过  隔离流程成立
真实 Shadow 通过    真实数据在受控范围成立
生产切换完成        新旧对账、健康检查、失败注入和回滚均通过
```

不得把前四层的结论写成生产正式切换。

## 十二、证券类型适用性

证券类型不是任务流程的替代物。任务仍负责决定本次处理范围，资产类型配置只说明某类证券对数据集或指标的适用性：

```text
required       必须具备，缺失会影响任务或质量
optional       有则使用，缺失不阻断任务
not_applicable 不适用，不计入缺失或健康失败
```

当前 profile 位于 `config/asset_profiles/`，支持 `stock`、`etf` 和 `index`。例如股票和 ETF 都可计算日线和技术指标，但公司财务指标对 ETF 可以是 `not_applicable`，不能按普通股票缺失处理。
