# 核心页面 UI 设计与前端契约 V1

> 本文只定义目标设计、稳定的前端契约和页面验收规则。
>
> 不记录当前实现进度、测试数字、提交记录或遗留问题。当前代码状态见 `UI_IMPLEMENTATION_STATUS.md`；未完成事项见 `FRONTEND_ENGINEERING_BACKLOG.md`。
>
> 产品定位：个人自用的 A 股投资分析工作台，重点是数据可信、研究可复现、操作可追溯和避免误操作。不设计多用户协作、角色审批、访问埋点或用户行为分析。

## 1. 设计总则

### 1.1 页面阅读顺序

所有业务页面统一遵循：

```text
当前结论 → 关键数据 → 解释证据 → 可执行动作 → 技术详情
```

页面不把数据库表、文件分区、内部对象名直接作为用户信息架构。

### 1.2 视觉方向

参考数据中心、DeepSeek 和 Claude 的共同特点：克制、清晰、信息密度高、结论优先。

| 项目 | 规范 |
|---|---|
| 页面背景 | 浅灰背景，白色内容面板 |
| 主色 | 蓝色，用于主操作、链接和信息提示 |
| 涨跌/盈亏 | A 股习惯：上涨/盈利红色，下跌/亏损绿色 |
| 警告 | 橙色 |
| 异常 | 红色 |
| 未知/暂无 | 灰色 |
| 内容形式 | 表格、摘要、详情抽屉、分段 Tab 优先 |
| 图表 | 用于解释数据，不代替结论和表格 |
| 文案 | 短句、总结性语言，明确原因和下一步 |

### 1.3 产品边界

- 工作台只汇总事实、建议和入口，不直接修改真实持仓。
- 市场发现产生候选，不直接产生真实交易。
- 观察池保存观察关系，不等同于自选、模拟或持仓。
- 模拟保存计划和模拟结果，不产生真实持仓。
- 持仓页面展示和提交真实事务，事实由持仓/账户服务负责。
- AI只负责总结结构化结果，不计算指标、不覆盖策略决策、不隐藏数据缺失。

## 2. 全局信息架构

### 2.1 一级导航

```text
工作台
市场
观察池
持仓
研究
复盘
系统
```

### 2.2 页面归类

| 一级领域 | 主入口 | 二级页面 |
|---|---|---|
| 工作台 | `/workbench` | `/` 无参数时进入工作台，带股票参数进入个股分析 |
| 市场 | `/market` | `/market-discovery`、`/compare` |
| 观察池 | `/watch-pool` | `/watch-pool/market`、`/watchlist`、`/simulation` |
| 持仓 | `/positions` | `/positions/add`、`/positions/{id}`（持仓详情） |
| 研究 | `/research` | `/analyze`、`/research/detail`、`/indicator-center`、`/strategy-composer`、`/strategy`、`/operation-points` |
| 复盘 | `/review` | `/morning-report`、`/log`、`/quicklog` |
| 系统 | `/system` | `/data-center`、`/data-center/assets`、`/data-center/tasks`、`/notify-center`、`/diagnostics`、`/settings` |

旧路由不属于目标设计。切换时直接下线；不为 `/dashboard/*`、`/portfolio` 等旧地址设计兼容页面或长期重定向。用户主导航中只出现新入口。

### 2.3 最终页面壳层

除登录页外，所有页面最终使用同一壳层：

```text
深色侧栏
→ 一级业务导航
→ 当前领域二级导航
→ 页面标题、说明、刷新和主操作
→ 摘要区
→ 主表格或主工作区
```

工作台、数据中心和任务中心可以拥有不同的内容容器，但导航项、命名、高亮、断点和交互行为必须一致。不再长期依赖 CSS 覆盖旧模板来模拟公共壳层。

## 3. 页面设计

### 3.1 工作台

#### 用户问题

> 今天有什么需要优先关注或处理？

#### 页面结构

```text
今日摘要
→ 今日待办
→ 持仓风险
→ 观察池变化
→ 数据健康
→ 通知状态
→ 快捷操作
```

#### 关键字段

| 区域 | 字段 |
|---|---|
| 摘要 | 总体状态、数据截至日期、摘要结论 |
| 待办 | 优先级、来源、事项、原因、数据日期、下一步 |
| 持仓 | 标的、建议、风险状态、建议原因 |
| 观察池 | 标的、来源、当前状态、下一动作 |
| 数据 | 数据项、最新实际日期、健康状态 |
| 通知 | 待投递、失败、死信 |

市场摘要没有真实数据时显示“市场摘要暂未接入”，不生成占位结论。

### 3.2 市场

#### 用户问题

> 市场整体、指数和板块当前有什么变化？

#### 页面结构

```text
日期与数据状态
→ 指数表现表
→ 板块表现表
→ 成交/资金摘要
→ 指数和板块图表
→ 进入市场发现
```

图表必须标注数据日期、来源和空数据状态。没有统一市场状态事实时，不自行拼接“强多/弱空”等结论。

### 3.3 市场发现

#### 用户问题

> 在指定日期和条件下，哪些股票满足条件，为什么满足？

#### 页面结构

```text
筛选条件
→ 条件摘要
→ 运行状态
→ 命中数量
→ 候选表格
→ 候选详情/K线
→ 研究、观察、模拟入口
```

#### 候选表格

| 列 | 内容 |
|---|---|
| 标的 | 代码、名称、市场、行业 |
| 行情 | 最新价、涨跌幅、成交额、换手率 |
| 指标 | 量比、均量比、PE、PB等实际可用字段 |
| 命中条件 | 条件名、实际值、判断 |
| 数据 | 实际数据日期、质量状态 |
| 下一步 | K线、分析、加入观察 |

空列表只表示“执行成功但无命中”；参数错误、字段缺失、数据滞后和服务失败必须分别展示。

### 3.4 观察池

#### 用户问题

> 哪些对象正在跟踪，它们从哪里来，下一步是什么？

#### 页面结构

```text
观察摘要
→ 数据健康提示
→ 状态筛选
→ 观察对象表格
→ 对象详情
```

#### 观察对象表格

| 列 | 内容 |
|---|---|
| 标的 | 代码、名称 |
| 来源 | 策略、自选、筛选候选等，可多来源 |
| 时间 | 加入时间、观察起点 |
| 状态 | 候选、观察中、待模拟、待建仓、已持仓 |
| 行情 | 实际价格、数据日期、市场状态 |
| 风险 | 数据滞后、风险灯、暂停原因 |
| 下一步 | 研究、模拟、持仓 |

观察池、观察池行情和自选分别负责对象观察、行情增强视图和关注关系管理，不维护重复事实。

### 3.5 持仓

#### 用户问题

> 当前持有什么，风险在哪里，建议是什么？

#### 页面结构

```text
账户摘要
→ 风险摘要
→ 当前持仓表格
→ 操作建议
→ 最近交易
→ 持仓详情
```

#### 持仓表格

| 列 | 内容 |
|---|---|
| 标的 | 代码、名称 |
| 数量 | 总数量、可用数量 |
| 成本 | 成本价、成本金额 |
| 行情 | 当前价、市值、浮动盈亏 |
| 仓位 | 仓位比例 |
| 风险 | 正常、防守、危机 |
| 建议 | 持有、加仓、减仓、清仓、调止损 |
| 操作 | 详情、交易、平仓 |

“持仓”是唯一用户可见名称。持仓摘要不直接修改事实，所有交易操作进入既有事务流程。

### 3.6 模拟

#### 用户问题

> 如果按某个策略和假设执行，结果如何？

#### 页面结构

```text
模拟计划
→ 运行状态
→ 模拟结果
→ 成交/事件
→ 收益曲线
→ 创建真实建仓流程
```

页面必须明确“模拟结果不等于真实持仓”，显示策略版本、数据区间、数据日期和执行状态。进入建仓只打开真实事务表单，不等于已经建仓。

### 3.7 复盘

#### 用户问题

> 已发生的交易结果如何，哪些决策有效，哪里存在执行偏差？

#### 页面结构

```text
复盘结论
→ 收益统计
→ 持仓周期/交易流水
→ 执行偏差
→ 复盘证据
→ 导出
```

统计必须显示口径：真实交易、已实现盈亏、FIFO、统计范围。真实交易、模拟结果和建议记录必须明确区分。

### 3.8 晨报、操作日志和快速记录

| 页面 | 职责 |
|---|---|
| 晨报 | 只读汇总市场、持仓、观察池、通知和数据日期 |
| 操作日志 | 记录业务操作、建议、成交、原因和结果 |
| 快速记录 | 快速录入操作笔记，不替代结构化交易记录 |

### 3.9 研究中心与个股研究

研究中心是研究工具入口；个股研究是结构化 ResearchRun 结果页面。

个股研究页面顺序：

```text
标的和来源
→ 研究状态
→ 技术/市场/估值/基本面结论
→ 策略决策
→ 研究证据
→ 数据可信上下文
→ 观察快照/模拟计划/报告
```

基本面未接入时显示“延期”，估值受限时显示“部分可用”或“暂无数据”，不能显示为正常。

### 3.10 指标中心

```text
指标目录
→ 定义和统一口径
→ 表达式编辑
→ 样本预览
→ 启用状态
```

内置指标只读；自定义指标保存、启用、停用和删除分开处理。删除内置指标不提供入口。

### 3.11 策略编排

```text
方案信息
→ 入场规则
→ 退出规则
→ 风控和仓位
→ 校验
→ 影响范围
→ 发布/回滚
```

草稿、校验通过、已发布和启用是不同状态，页面不得用一个“保存成功”覆盖它们。

### 3.12 策略实验和操作点位

策略实验：

```text
实验参数 → 扫描 → 回测 → 收益曲线 → 交易明细
```

扫描、回测和图表请求分别展示状态。操作点位：

```text
标的和参数 → 当前点位 → 支撑/止损/目标 → RR → 历史回测
```

参数分析结果必须标注是否已保存为策略版本。

### 3.13 通知中心

通知中心分为三个 Tab：

```text
业务通知 | 系统告警 | 投递台账
```

投递状态和用户是否处理不是同一概念。当前 V1 只要求展示投递事实和重试，不扩展用户行为审计。

### 3.14 数据中心

#### 用户问题

> 系统有哪些实际数据和指标，最新到哪里，覆盖是否足够，当前是否可信？

#### 页面结构

```text
总体健康摘要
→ 数据资产统计
→ 重点数据资产表格
→ 待关注数据项
→ 当前生产链路
→ 数据资产详情抽屉
```

#### 资产表格

| 列 | 内容 |
|---|---|
| 数据资产 | 展示名称、资产 key |
| 分类 | 基础行情、指标、估值、基本面、资金流、研究因子等 |
| 最新实际日期 | 实际数据截至日期 |
| 覆盖 | `covered / expected`、比例；没有统计时显示暂无覆盖数据 |
| 健康状态 | 正常、待更新、部分可用、异常、状态未知 |
| 关联任务 | 生产任务名称 |
| 更新时间 | 健康事实更新时间 |

#### 详情和操作

详情抽屉包含定义、健康、证券类型覆盖、来源与消费、业务影响、最近版本和当前结果预览。预览只读、限制行数和允许目录，前端不直接读取文件。

| 操作 | 页面要求 |
|---|---|
| 增量同步/重建 | 显示数据集、日期范围、提交状态和结果 |
| 发布/回滚 | 显示版本、质量、影响范围和确认面板 |
| 查看关联任务 | 携带资产 key 进入任务中心 |

### 3.15 任务中心、诊断和系统设置

| 页面 | 核心问题 |
|---|---|
| 数据中心 | 数据有哪些、最新到哪里、覆盖和健康如何 |
| 任务中心 | 任务配置、执行、进度、日志和产物如何 |
| 运行诊断 | 应用、调度、数据、通知是否正常 |
| 系统 | 系统工具入口和职责是什么 |
| 系统设置 | 策略、规则、通知、账户和运行配置是什么 |

数据中心和任务中心使用系统工作区表格和详情抽屉；诊断只读；设置承担配置读写，危险操作单独隔离。

| 页面 | 用户问题 | 主要内容 |
|---|---|---|
| 任务中心 | 任务配置和运行到了哪一步？ | 任务分组、状态、进度、日志、产物和配置 |
| 运行诊断 | 应用、调度、数据和通知是否正常？ | 状态摘要、状态表、进入处理页 |
| 系统设置 | 当前策略、通知和账户配置是什么？ | 分组表单、保存反馈、危险操作区 |

## 4. 页面间流程与上下文

### 4.1 主流程

```text
市场发现
→ 候选详情
→ 观察池
→ 研究
→ 模拟计划
→ 模拟结果
→ 进入建仓流程
→ 真实持仓
→ 复盘
```

### 4.2 PageContext

页面之间使用统一上下文：

| 字段 | 说明 |
|---|---|
| `entity_id` | 当前对象 ID |
| `source_type` | 来源类型，如 screen/candidate/observation |
| `source_id` | 来源记录 ID |
| `snapshot_id` | 固化的上下文快照 |
| `data_as_of` | 事实数据日期 |
| `dataset_version` | 数据版本 |
| `strategy_version` | 策略版本 |
| `return_to` | 返回页面和筛选上下文 |
| `context_expired` | 上下文是否已过期 |

实体来源必须由后端事实确认，URL 只传递引用和导航信息，不作为来源事实本身。

## 5. 状态、口径和请求契约

### 5.1 状态词表

| 状态 | 文案 | 颜色 |
|---|---|---|
| `healthy` | 正常 | 绿 |
| `stale` | 待更新 | 橙 |
| `partial` / `partial_success` | 部分可用 | 橙 |
| `critical` | 异常 | 红 |
| `failed` | 失败 | 红 |
| `running` | 运行中 | 蓝 |
| `requested` | 等待执行 | 蓝 |
| `deferred` | 延期 | 灰 |
| `disabled` | 未启用 | 灰 |
| `empty` | 暂无数据 | 灰 |
| `not_applicable` | 不适用 | 灰 |
| `cancelled` | 已取消 | 灰 |
| `unknown` | 状态未知 | 灰 |
| `waiting_close` | 等待收盘 | 灰/信息 |
| `unavailable` | 暂无数据 | 灰 |
| `degraded` | 部分可用 | 橙 |
| `ok` | 正常 | 绿 |
| `success` | 健康场景：正常；运行场景：已完成 | 绿 |

状态 CSS、JS 词表和页面文案必须使用同一映射。`success` 的文案由业务上下文决定：健康结果显示“正常”，任务或研究运行结果显示“已完成”。`waiting_close` 是业务等待状态，不覆盖数据健康状态；`unavailable` 等价于暂无数据；`degraded` 等价于部分可用。

状态类名唯一采用：

```text
.status-tag.status-healthy
.status-tag.status-partial
.status-tag.status-running
```

不再使用 `.tag.status-*`、`.dm-health.*` 或 `.status-tag.ok` 作为目标类名。旧类名不保留兼容别名，迁移时直接替换并删除。

状态 key 与唯一视觉 class 的映射如下：

| 状态 key | 展示文案 | 唯一视觉 class |
|---|---|---|
| `healthy` / `ok` / 健康场景 `success` | 正常 | `status-healthy` |
| `stale` | 待更新 | `status-stale` |
| `partial` / `partial_success` / `degraded` | 部分可用 | `status-partial` |
| `critical` / `failed` | 异常/失败 | `status-critical` / `status-failed` |
| `running` / `requested` | 运行中/等待执行 | `status-running` |
| `deferred` | 延期 | `status-deferred` |
| `disabled` | 未启用 | `status-disabled` |
| `empty` / `unavailable` | 暂无数据 | `status-empty` |
| `not_applicable` | 不适用 | `status-not-applicable` |
| `cancelled` | 已取消 | `status-cancelled` |
| `waiting_close` | 等待收盘 | `status-waiting-close` |
| 运行场景 `success` | 已完成 | `status-healthy` |

### 5.2 多维状态

数据可用性、数据新鲜度、任务执行、权限和操作门禁是不同维度，不压成一个状态：

```text
主状态：运行中
数据状态：待更新
任务状态：运行中
操作状态：禁止重复执行
```

主状态优先级：

```text
权限拒绝 → 运行中 → 失败 → 异常 → 部分可用 → 待更新 → 正常 → 暂无数据 → 状态未知
```

### 5.3 操作分级与状态门禁

| 级别 | 示例 | 反馈要求 |
|---|---|---|
| 查看 | 查看详情、K线、日志 | 直接打开详情区域或抽屉 |
| 轻量写入 | 保存模板、加入观察 | 页面内显示成功/失败，保留上下文 |
| 运行操作 | 执行筛选、运行模拟、任务重试 | 显示提交中、运行中、终态和运行编号 |
| 配置操作 | 启停任务、保存并生效、发布策略 | 显示影响范围并二次确认 |
| 高风险操作 | 删除、回滚、重置、平仓 | 危险确认面板，说明可恢复性 |

| 状态 | 查看 | 重新运行/刷新 | 发布/建仓 | 删除/回滚 |
|---|---|---|---|---|
| 正常/已完成 | 允许 | 按业务规则 | 允许业务校验 | 需要确认 |
| 待更新 | 允许 | 允许 | 显示日期风险 | 需要确认 |
| 部分可用/降级 | 允许 | 允许 | 提示缺失能力，按业务规则阻止 | 需要确认 |
| 异常/失败 | 允许 | 允许重试 | 默认阻止依赖该结果的操作 | 需要确认 |
| 运行中 | 允许 | 禁止重复运行 | 默认阻止 | 默认阻止 |
| 等待收盘 | 允许 | 等待条件满足 | 默认阻止依赖收盘数据的操作 | 按业务规则 |
| 未启用 | 允许 | 手动执行需说明不会自动调度 | 默认阻止 | 按业务规则 |
| 暂无数据/未知结果 | 允许空态 | 查询后再操作 | 默认阻止 | 按业务规则 |

操作状态使用 `allowed`、`disabled`、`blocked`、`denied`、`pending`、`unknown`；`denied` 仅表示当前操作不可执行，不扩展多用户角色模型。

中文门禁文案与机器状态必须按以下规则映射：

| 中文表现 | 机器状态 | 是否展示按钮 | 说明 |
|---|---|---|---|
| 允许 | `allowed` | 是 | 当前上下文可直接执行 |
| 暂不可用 | `disabled` | 否/禁用 | 条件未满足，但不是规则阻断 |
| 已阻止 | `blocked` | 否 | 被数据、运行状态或业务规则阻止 |
| 无权限 | `denied` | 否 | 当前登录状态不允许 |
| 等待确认 | `pending_confirmation` | 是 | 用户尚未确认，尚未发出请求 |
| 提交中 | `pending` | 否 | 请求已发出，结果尚未确认 |
| 结果未知 | `unknown` | 否 | 不得自动重复提交，先查询状态 |

`pending_confirmation` 是用户确认前状态，不能与请求已经发出的 `pending` 混用。

### 5.4 数值和日期

| 情况 | 展示 |
|---|---|
| `null`/未返回 | 暂无，不参与计算 |
| 真实 0 | 0，正常参与计算 |
| 分母为 0 | 不适用 |
| 类型不适用 | 不适用，不计入缺失 |
| 当前价缺失 | 当前价、市值、浮动盈亏和盈亏率均显示暂无 |
| `data_as_of` | 数据截至 |
| `requested_start/end` | 查询范围 |
| `latest_actual_date` | 最新实际日期 |
| `updated_at` | 更新时间 |
| `started_at/finished_at` | 运行时间 |

前端不重复计算持仓市值、收益、FIFO、候选命中、模拟收益和数据新鲜度。

### 5.5 API 响应和请求

目标响应信封：

```json
{
  "status": "success",
  "data": {},
  "error": null,
  "request_id": "..."
}
```

前端统一使用请求适配器；页面不各自判断多套信封。运行操作必须返回可查询的 `run_id` 或明确的结果未知状态。

请求时序：

```text
页面骨架
→ 主数据
→ 摘要/表格
→ 按需详情
→ 写入/运行
→ 局部刷新
```

一个区域失败不清空其他成功区域；轮询只针对 `requested/running`，进入终态立即停止。

### 6.1 CSS Token

基础实现统一落在公共 CSS，使用以下语义变量：

```css
--color-up: #dc3545;
--color-down: #28a745;
--color-success: #28a745;
--color-warning: #e67e22;
--color-danger: #dc3545;

--color-text-subtle: #6b7280;
```

### 6.4 表单

每个字段必须有标签、控件、单位/格式说明、就地错误、提交状态和结果反馈。

| 状态 | 表现 |
|---|---|
| 必填未填 | 字段下方显示具体提示 |
| 格式错误 | 不提交请求，保留输入 |
| 提交中 | 按钮禁用并显示处理中 |
| 成功 | 显示保存对象/版本 |
| 失败 | 显示可读原因，保留输入 |
| 未保存变更 | 离开前提示，不自动保存 |

### 6.5 确认和输入面板

删除、回滚、平仓、发布、重置和真实交易使用确认面板；价格、日期、原因和定义使用输入面板。面板必须显示对象、范围、影响、可恢复性、当前数据/配置版本、取消和确认按钮。

### 6.6 图表

| 图形 | 颜色 |
|---|---|
| K线阳线 | `--color-up` |
| K线阴线 | `--color-down` |
| MA5/10/20/60 | 紫/蓝/橙/深绿固定色 |
| 支撑位 | 信息蓝 |
| 止损位 | 危险红 |
| 目标/止盈位 | 警告橙 |
| 买卖信号 | 红/绿并带文字，不只靠颜色 |

图表必须有数据范围、来源、日期和文字摘要；容器重建前释放旧实例。

图表中的方向颜色和状态颜色必须通过视觉形态区分：

| 场景 | 颜色 | 形态 | 文字要求 |
|---|---|---|---|
| 上涨/盈利 | `--color-up` | 带 `+` 号的数值或阳线 | 必须显示正负号或方向 |
| 下跌/亏损 | `--color-down` | 带 `-` 号的数值或阴线 | 必须显示正负号或方向 |
| 数据异常 | `--color-danger` | 状态标签底色/边框 | 必须显示“异常/失败” |
| 数据警告 | `--color-warning` | 状态标签底色/边框 | 必须显示“待更新/部分可用” |

上涨/盈利不使用实心状态标签冒充异常；异常不只用红色数字表达。数值使用方向符号，状态使用标签和状态文字，避免同色误读。

## 7. 响应式、性能与可访问性

### 7.1 断点

| 断点 | 规则 |
|---|---|
| `>1050px` | 侧栏 + 主内容，摘要最多四列 |
| `761-1050px` | 摘要三列，复杂区域两列 |
| `<=760px` | 导航横向滚动，摘要两列，详情全屏 |
| `<=420px` | 摘要单列/两列，操作收进更多菜单 |

移动端表格必须定义必留字段；可折叠字段进入详情，不靠无限缩小字号解决。

| 页面类型 | 必留字段 | 可折叠字段 |
|---|---|---|
| 市场 | 指数/板块名称、最新价、涨跌幅、数据日期 | 成交额、次要指标 |
| 市场发现 | 标的、最新价、涨跌幅、命中条件、下一步 | PE/PB、次要成交指标 |
| 观察池 | 标的、来源、状态、数据健康、下一动作 | 支撑位、完整模拟字段 |
| 持仓 | 标的、数量、当前价、盈亏、风险、建议 | 成本详情、历史流水 |
| 模拟 | 标的、策略、状态、收益、下一步 | 完整事件和参数 |
| 复盘 | 日期、标的、方向、结果、盈亏 | 手续费、辅助诊断 |
| 任务中心 | 任务、状态、进度、最近结果、操作 | 配置代码、完整时间字段 |
| 通知中心 | 时间、标题、状态、重试 | payload、通道详情 |
| 研究工具 | 标的/方案、状态、核心结果、下一步 | 原始表达式、输入快照 |

### 7.2 性能目标

| 项目 | 目标 |
|---|---|
| 页面骨架 | 300ms 内出现 |
| 普通主数据 | 2s 内完成或显示进度/重试 |
| 工作台摘要 | 2s 内可读 |
| 数据中心/任务中心 | 2s 内可读，详情按需加载 |
| 市场发现 | 立即显示运行中，完成后分页渲染 |
| 持仓 | 默认不加载全部详情图表 |
| 通知/复盘历史 | 分页或限制条数 |

### 7.3 可访问性

- 状态必须同时有文字，不能只依赖颜色。
- 按钮、输入框、Tab、抽屉和确认面板支持键盘操作。
- 抽屉打开后焦点进入，关闭后返回触发按钮。
- 错误和运行状态使用适当的 `aria-live`。
- 表格有表头、单位和可理解的列名。
- 图表提供日期、来源和文字摘要。
- 禁用按钮说明原因。

## 8. 页面完成判定

页面只有同时满足以下条件，才能标记为完成：

| 条件 | 要求 |
|---|---|
| 结构 | 符合页面线框和职责 |
| 壳层 | 使用统一导航和响应式壳层 |
| Token | 使用公共颜色、状态和组件类名 |
| 数据 | 关键事实有唯一来源，日期和缺失值明确 |
| 交互 | 主要操作有提交中、成功、失败、结果未知 |
| 安全 | 内联事件数据安全，Markdown 已净化，敏感配置不回显 |
| 状态 | loading/empty/error/partial/terminal 可区分 |
| 移动端 | 关键字段、详情、筛选和操作可用 |
| 自动化 | 页面契约和相关业务测试通过 |
| 运行验证 | 路由、静态资源和核心交互冒烟通过 |

HTTP 200、模板能渲染或单元测试通过，只是必要条件，不能单独代表页面完成。
