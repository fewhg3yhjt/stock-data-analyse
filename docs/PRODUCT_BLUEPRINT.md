# 投资分析工具产品总纲 V1

## 1. 文档定位

本文是产品总纲，不描述具体算法实现，也不替代各子模块设计文档。所有子模块必须遵守 [领域模型与统一契约](DOMAIN_MODEL_AND_CONTRACTS.md)。

本文只回答：

1. 工具要解决什么问题。
2. 用户主流程是什么。
3. 系统由哪些业务模块组成。
4. 模块之间如何衔接。
5. 哪些对象是事实，哪些对象是计算结果。
6. 哪些能力属于第一版必须跑通的范围。

数据采集、清洗、版本、质量和发布模块视为数据平面基础设施。业务模块必须使用 [业务数据输入契约](DATA_INPUT_CONTRACTS.md) 中已经存在的真实读取对象，不得另造数据读取接口。

领域对象、公共术语、状态转换和跨模块接口以 [领域模型与统一契约](DOMAIN_MODEL_AND_CONTRACTS.md) 为准；历史文档中与本文冲突的同名对象以本文为准。

## 2. 产品目标

工具是一个面向个人投资研究和执行复盘的工作台，核心闭环是：

```text
发现股票
→ 查看走势和指标
→ 配置或选择策略
→ 产生买卖判断
→ 回测/模拟策略收益
→ 加入观察池
→ 记录真实持仓和交易
→ 对比实际收益、策略收益和市场收益
→ 通过消息通知获得提醒
→ 复盘决策与执行
```

第一版不追求自动交易，而是确保用户可以用同一套策略完成研究、模拟、持仓判断和复盘。现有 `BACKEND_RESEARCH_SIMULATION_STRATEGY_V1.md`、`domain/`、`services/`、`repositories/backend_domain.py` 不属于新系统运行时，只用于一次性历史数据评估；迁移完成后下线。

## 3. 核心原则

### 3.1 策略与执行场景分离

策略只负责根据输入上下文产生标准决策：

```text
输入数据和持仓上下文
→ 评估条件
→ 产生 BUY / SELL / HOLD / WAIT 等决策
```

选股、回测、模拟和实盘建议是不同执行场景，不能各自复制一套买卖规则。

### 3.2 事实与推导分离

事实包括：

- 已发布行情和指标数据；
- 用户配置的策略版本；
- 用户实际录入的交易；
- 账户现金变动；
- 用户确认的操作。

推导包括：

- 选股结果；
- 指标计算结果；
- 策略决策；
- 模拟交易；
- 持仓市值和收益；
- 晨报和通知内容。

推导结果必须记录生成时间、输入版本和参数快照，不能伪装成事实。

### 3.3 一个策略，一个决策协议

V4.5、V6、操作点位等旧算法不进入新系统运行时。需要的能力按新协议直接重写，最终所有策略实现都输出统一的 `StrategyDecision`。

### 3.4 回测和模拟使用同一交易模拟内核

回测和模拟都表示：

```text
给定策略、数据、资金和执行规则，推进交易日并计算虚拟账户结果
```

差异只体现在日期范围和运行目的，不允许使用两套收益口径。

### 3.5 用户看到的每个结论都要能解释

重要结果必须可回答：

```text
使用了哪个策略版本？
使用了哪份数据？
数据截至哪一天？
触发了哪些条件？
采用了什么价格和资金假设？
结果是否来自真实交易、模拟还是推导？
```

## 4. 产品模块

### 4.1 数据基础设施

职责：提供已发布、可追溯、可校验的数据集。

输入：外部市场数据、基本面数据、辅助数据。

输出：

- `stock_daily`；
- `valuation_daily`；
- `indicators`；
- `factors`；
- 数据版本、质量状态和 `data_as_of`。

业务模块不直接处理 Raw Batch，也不直接绕过 Published Dataset。

### 4.2 选股与行情分析

职责：根据条件产生候选，并提供走势、指标和命中原因。

输出：

- 筛选运行记录；
- 候选股票；
- 命中条件和指标值；
- 图表；
- 加入观察池或进入回测的入口。

不负责完整买卖策略和真实持仓。

### 4.3 指标与条件

职责：定义指标、计算指标、判断条件，并为策略和选股提供统一输入。

输出：

- 指标定义和版本；
- 指标值；
- 条件判断；
- 条件解释。

不直接产生交易动作。

### 4.4 策略与方案编排

职责：将指标条件组合成可版本化的策略，包括入场、出场、风控、仓位和执行规则。

输出：

- 策略版本；
- 校验结果；
- 发布状态；
- 可执行策略对象。

### 4.5 回测与模拟

职责：使用策略和虚拟账户推进历史交易，输出交易明细、权益曲线和绩效指标。

输出：

- 模拟运行；
- 模拟交易；
- 模拟事件；
- 收益和风险指标；
- 与基准的比较。

不修改真实账户和持仓。

### 4.6 观察池

职责：承接选股结果和人工关注，管理从候选到模拟、再到建仓参考的中间流程。

输出：

- 当前观察对象；
- 来源和原因；
- 有效期；
- 最新研究/模拟结果；
- 下一步动作。

### 4.7 真实账户、持仓与交易

职责：记录用户实际发生的交易，计算当前持仓、现金和资产结果。

输出：

- 账户和组合；
- 持仓周期和批次；
- 实际成交；
- 现金流水；
- 当前资产和收益；
- 持仓建议。

第一版交易由用户手工录入，不接券商自动交易。

### 4.8 建议与消息通知

职责：保存策略决策和持仓建议，将业务事件通过邮件等渠道投递。

输出：

- 建议记录；
- 通知事件；
- 投递记录；
- 失败重试和死信。

通知不重新计算策略，只消费标准化决策和报告。

### 4.9 收益分析与复盘

职责：比较真实操作、策略模拟和市场基准，解释执行偏差和最终结果。

输出：

- 账户收益；
- 策略收益；
- 基准收益；
- 交易周期复盘；
- 建议执行偏差；
- 策略改进依据。

### 4.10 平台支撑

包括任务中心、数据中心、系统健康、配置、权限和备份。它们支撑业务运行，但不应反向定义投资业务语义。

## 5. 主流程和实体关系

```text
ScreenDefinition
    → ScreenRun
        → ScreenCandidate
            → Observation
                → SimulationRun
                    → PositionCycle
                        → Execution
                            → Advice / Review
```

策略在多个执行场景中复用：

```text
StrategyVersion
    ├── ScreenRun
    ├── ResearchRun
    ├── SimulationRun
    ├── AdviceEvaluation
    └── Execution / Review reference
```

## 6. 统一核心实体

### StrategyVersion / StrategyDecision

正式字段、输入值快照和解释轨迹只在 [领域模型与统一契约](DOMAIN_MODEL_AND_CONTRACTS.md) 中定义。本总纲只引用，不重复定义字段。

动作至少包括：

```text
WATCH
BUY
BUY_MORE
SELL_PARTIAL
SELL_ALL
HOLD
WAIT
NO_ACTION
```

### SimulationRun

一次虚拟交易运行，锁定：

```text
run_id
strategy_version
universe
start_date
end_date
initial_cash
execution_rules
cost_config
benchmark
data_context
status
```

### PositionCycle

一轮真实投资周期：

```text
建仓
→ 加仓/减仓
→ 持有
→ 部分止盈或止损
→ 清仓
→ 复盘
```

同一股票多次建仓应形成不同周期，不能把所有历史交易混成一条当前持仓记录。

## 7. 状态边界

### 策略版本

```text
                              └→ disabled → archived
```

### 模拟运行

```text
requested → running → success
                    ├→ partial_success
                    ├→ failed
                    └→ cancelled
```

### 观察对象

```text
                  ├→ paused
                  ├→ expired
                  └→ removed
```

### 真实持仓

```text
planned → accumulating → holding
                         ├→ left_take_profit
                         ├→ right_trailing
                         ├→ stopped
                         └→ closed → reviewed
```

## 8. 第一版范围

必须跑通：

1. 条件选股并查看走势图。
2. 创建结构化策略并保存版本。
3. 策略对单只股票或股票集合产生买卖决策。
4. 使用同一策略执行回测/模拟。
5. 展示策略收益、基准收益和交易明细。
6. 将候选加入观察池。
7. 手工录入真实成交并查看持仓和整体收益。
8. 对比真实收益、模拟收益和基准收益。
9. 产生买卖建议并发送邮件。
10. 保存建议、交易和复盘所需的版本与日期信息。

暂不要求：

- 券商自动交易；
- 任意 Python 策略脚本；
- 多租户和复杂 RBAC；
- 机器学习策略；
- 复杂订单撮合；
- 多套正式策略引擎并行运行。

## 10. 全局验收

用户能够完成：

```text
打开选股页面
→ 使用条件筛选
→ 查看股票走势
→ 选择或创建策略
→ 运行回测/模拟
→ 查看收益和大盘对比
→ 加入观察池
→ 生成买入判断
→ 录入真实建仓
→ 查看持仓收益
→ 录入卖出
→ 比较实际、策略和基准收益
→ 收到邮件通知
→ 查看完整复盘链路
```

任何核心结果都能追溯到策略版本、数据版本、数据截止日和实际输入参数。
